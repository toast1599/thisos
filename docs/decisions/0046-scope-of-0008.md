# 0046. Scope of 0008: the OS's own code, including platform-specific code

- **Status:** Accepted, amended by [0152](0152-kernel-log-and-reset.md) and [0213](0213-power-capability.md)
- **Date:** 2026-10-15

## Context

[0008](0008-architecture-neutral-design.md) confines architecture-specific concepts to architecture-specific code. [01-objective](../design/01-objective.md) left two questions about its reach open:
- Does it apply to third-party programs?
- Does it cover platform-specific code, such as interrupt controllers, timers and firmware tables?

## Options

- **Who it applies to:** the OS's own code only, or all code.
- **What it covers:** platform-specific code like CPU-specific code, or CPU architectures only.

## Decision

- **0008 applies to the OS's own code.** Third-party programs may use architecture-specific code, such as SIMD, as they like. They still build separately for each architecture ([0039](0039-native-per-arch.md)).
- **0008 also covers platform-specific code.** Interrupt controllers, timers and firmware tables live only in platform-specific modules, under the same rules as architecture-specific code.

## Consequences

- **The build checks follow this scope.** The checks in [07-engineering](../design/07-engineering.md) cover the OS's own code, platform-specific code included.
- **The kernel's platform-specific code is small.** Under [0032](0032-minimal-hardware-discovery.md), it is limited to the interrupt controller, the timer and reading the memory map.
- **"The OS's own code" means the system image,** as in [0044](0044-system-image-is-os-shipped.md).
