# 0009. x86_64 is the first architecture

- **Status:** Accepted, amended by [0271](0271-corrections.md)
- **Date:** 2026-10-14

## Context

The design is architecture-neutral ([0008](0008-architecture-neutral-design.md)), but the implementation has to start on one architecture. The development machine is x86_64, and KVM works on it, so x86_64 guests run in QEMU at close to native speed.

## Options

1. x86_64
2. AArch64
3. RISC-V

## Decision

Option 1. x86_64 is the first architecture. A second architecture comes later, but not too late. Which architecture it will be, and the point at which it has to be up, are still open ([01-objective](../design/01-objective.md)).

## Consequences

- [0008](0008-architecture-neutral-design.md) can't be tested by a real port until the second architecture exists.
- x86_64 is the forgiving architecture: memory ordering is strict and unaligned access works. Concurrency bugs in the trusted code can pass every test on x86_64 and still fail on AArch64 or RISC-V. The second architecture is what finds them.
- QEMU for AArch64 and RISC-V isn't installed on the development machine. Installing it is part of the second-architecture bring-up.
